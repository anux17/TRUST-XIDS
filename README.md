# TRUST-XIDS

A research-oriented network intrusion detection system investigating the
intersection of machine learning / deep learning intrusion detection,
explainable AI, cross-dataset generalization, and a custom,
operationally-defined measure of prediction trustworthiness (the
TRUST-XIDS Trust Score).

## Objective

Classify network traffic as benign or malicious using four mandatory
models (Random Forest, XGBoost, SVM, 1D-CNN), compare classical ML against
deep learning, explain model predictions with SHAP and LIME, investigate
cross-dataset generalization between UNSW-NB15 and CICIDS2017, and
quantify prediction trustworthiness with an explicit, measured, honestly
limited Trust Score — not a fabricated single number.

## Datasets

- **UNSW-NB15** — official train/test split, used as provided
  (`UNSW_NB15_training-set.csv`, `UNSW_NB15_testing-set.csv`).
- **CICIDS2017** — daily capture CSVs, no official split (an 80/20
  stratified split is created in Notebook 1). The loader reads *every* CSV
  present in the configured CICIDS folder, so this project runs correctly
  whether 1 or all 8 daily files are present — just with different numbers.

Both datasets are third-party research datasets; this project does not
redistribute them. Place your copies under `data/raw/unsw/` and
`data/raw/cicids/` (see Setup below), or point the config variables in
Notebook 1 at wherever they already live (including a Google Drive path on
Colab).

**Important:** this repository was built and partially validated against
the full UNSW-NB15 set plus only 2 of CICIDS2017's 8 daily files
(`Tuesday-WorkingHours` and `Thursday-WorkingHours-Morning-WebAttacks`).
Notebooks 1–4 executed successfully end-to-end on that data and their
outputs/summaries reflect it; Notebooks 5–7 were written and syntax
validated but not run against this partial data (direction from the
project owner was to run the complete pipeline directly against the full
8-file CICIDS2017 set, so no numbers are reported for CNN/SHAP/LIME/Trust
Score pending that run). **Drop the remaining 6 CICIDS2017 daily files into
`data/raw/cicids/` and re-run Notebooks 1 through 7 top to bottom** to get
final, complete numbers — no code changes are required.

## Notebook Execution Order

Run top to bottom, in order, from a fresh kernel. Each notebook reads only
files saved by an earlier one — there is no hidden dependency on variables
left over from a previous run.

1. **01 — Data Loading and Preprocessing**: loads both datasets, cleans
   missing/infinite/duplicate values, encodes categoricals, splits
   CICIDS2017 (UNSW keeps its official split), scales features (fit on
   train only), saves 8 CSVs + 5 fitted encoder/scaler objects.
2. **02 — Exploratory Data Analysis**: statistics, label/attack
   distributions, feature distributions, correlation, class imbalance —
   both datasets, separately.
3. **03 — Feature Selection**: drops near-constant/redundant columns
   within each dataset (keeping a full feature set, not a drastically
   reduced one), ranks by Random Forest importance, and builds the
   8-feature harmonized cross-dataset schema with unit verification, KS
   distribution comparison, and a final validation checklist.
4. **04 — Classical ML Models**: trains Random Forest, XGBoost, and SVM —
   within-dataset (full + harmonized features) and cross-dataset (both
   directions) — with consistent metrics across every run.
5. **05 — Deep Learning Model**: trains the mandatory 1D-CNN with the same
   experiment structure and metrics as Notebook 4.
6. **06 — Explainable AI**: SHAP (TreeExplainer for RF/XGBoost,
   KernelExplainer for SVM) and LIME, **scoped to the full UNSW-NB15
   feature set only** (per the project's documented scope decision — the
   harmonized set drops UNSW's two most important features, so explaining
   it would explain a deliberately impoverished model).
7. **07 — Trust Score and Final Evaluation**: integrates all prior
   results (no retraining), cross-dataset generalization discussion, the
   TRUST-XIDS Trust Score (defined, computed, sensitivity-tested,
   limitations stated), final visualizations and conclusions.

## Models Implemented

Random Forest, XGBoost, Support Vector Machine (RBF kernel), 1D
Convolutional Neural Network. No other models were substituted or added.

## Evaluation Methodology

Accuracy, balanced accuracy, precision, recall, F1-score, ROC-AUC,
confusion matrix, training/prediction time — reported for every
experiment (within-dataset full features, within-dataset harmonized
features, cross-dataset both directions), for every model. All
preprocessing (encoding, scaling, feature selection) is fit on training
data only and applied — never refit — to test data. SVM uses a documented
20,000-row stratified training subsample for computational feasibility
(test sets are always evaluated in full); this is stated explicitly in
Notebook 4, not hidden.

## Explainability Methods

SHAP (TreeExplainer for tree models, KernelExplainer for SVM) and LIME,
applied to the full UNSW-NB15 feature set only (see Notebook 6 scope
note above). Includes a feature-ablation test as a quantitative check of
whether SHAP's ranking reflects features the model actually depends on.

## Trust Score Methodology

A three-component score — Detection Reliability (within-dataset F1),
Generalization Consistency (cross-dataset/within-dataset F1 ratio), and
Explanation Stability (SHAP-vs-built-in-importance rank agreement) —
combined with documented, sensitivity-tested weights. Components that
cannot be measured for a given model (e.g. Explanation Stability for
SVM/1D-CNN in this run) are flagged as unavailable and the score is
re-normalized over available components, never fabricated. Full
mathematical definition, interpretation, and stated limitations are in
Notebook 7, Section 5.

## Output Artifacts

- `data/processed/*.csv` — cleaned, selected, and harmonized datasets;
  per-model results tables; Trust Score and sensitivity tables.
- `models/*.joblib`, `*.keras` — fitted models and preprocessing objects.
- `artifacts/explainability/*.csv` — SHAP importance tables and ablation
  test results.

## Limitations

- `sttl` and `ct_srv_dst` (UNSW-NB15's strongest features by both SHAP and
  built-in importance) have no CICIDS2017 equivalent, so the cross-dataset
  experiment cannot test whether they generalize — stated explicitly rather
  than worked around.
- Every harmonized cross-dataset feature shows a non-trivial KS statistic
  (0.20–0.71) between the two datasets even after unit conversion, so any
  cross-dataset performance drop is an expected, explained finding, not an
  unexamined anomaly.
- The Trust Score's Explanation Stability component is only available for
  Random Forest in the current run; SVM and 1D-CNN scores use a
  re-normalized two-component average and are flagged as such.
- Notebooks 5–7 have not yet been executed against the full CICIDS2017
  dataset (see the dataset note above) — run them to get final reported
  numbers.
- The Trust Score is a mathematically defined, internally consistent
  measure built from this project's own experiments. It is not a validated
  real-world security metric, and this is stated plainly rather than
  implied otherwise.
